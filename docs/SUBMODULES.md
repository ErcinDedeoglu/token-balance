# Submodules

Generated by `tooling/agent-kit/submodules.sh`. Rows come from `.gitmodules`.
Hand-edit only **Why** and **Boundary** — the script preserves those two columns.

Submodules are **foreign repositories**. Never write inside one. Per-submodule
knowledge lives in a sidecar directory: `docs/submodules/<slug>/`.

| Sidecar file | Owns | Update trigger |
|---|---|---|
| `NOTES.md` | What it is, what we consume, gotchas | You learn something from its code |
| `RUNBOOK.md` | Commands actually executed and observed | Run/upgrade mechanics verified or changed |
| `STEERS.md` | User direction about this submodule, quoted verbatim | The moment the user steers you |
| `HISTORY.md` | Task-neutral lessons mined from its past | An explicit history dig only |

`Notes` below compares each sidecar's reviewed-at stamp to the live pointer.
`MATCH` = verified at this commit. `MOVED +N` = the pointer advanced N commits
since anyone re-read the notes, so treat them as suspect. `UNREVIEWED` = never
stamped. After re-reading: `tooling/agent-kit/submodules.sh --review <path>`.

## Rules

1. No file the kit owns may exist inside a submodule path — no `AGENTS.md`, no lesson, no adapter.
2. A dirty submodule worktree is a failed change. Revert it or land it upstream and bump the pointer.
3. Behavior must change inside a submodule → bump to a released version, wrap it at the boundary in your own code, or file it upstream. Pick one and say so.
4. A pointer bump is a superproject change: name the old and new SHA and why, and log it in `memory/daily/`.
5. Adding or removing a submodule requires user approval.
6. A `MOVED` sidecar is a warning, not a blocker — but do not cite a stale note as fact. Re-read, then re-stamp.
7. Every `RUNBOOK.md` row is `verified <date>` or `UNVERIFIED`. An unverified row may exist; a wrong row that looks verified may not.
